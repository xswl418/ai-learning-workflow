# 设计原则与取舍

## 1. 把目标转成可观察的小能力

“学会某个专业”不足以直接指导一轮教学。工作流先明确实际用途，再形成可练习和检查的小能力。学习单元既可以是一类数学问题，也可以是一项分析操作，不强制所有知识都变成软件项目。

小能力的大小由实际表现调整。过大时补足前置，过碎时合并相关操作；完整过程始终可见，减少只完成局部动作却不知道用途的问题。

## 2. 先给整体，再逐渐减少帮助

新手需要看到概念、条件和步骤之间的关系。首次示范可以完整，后续练习逐渐留出方法选择和执行空间；困难时再增加帮助，不把减少提示当成固定倒计时。

分级提示保留思考机会，也允许学习者直接请求完整解答。提供解答后如实记录支持条件，不以拒绝解答强迫接受某种学习方式。

## 3. 能力目标与作答渠道分开

理解公式与输入公式是两件事。选择、辨析、操作和简短解释都能提供某些能力证据，但任何单一形式都有局限。

公式选择可以检查结构和适用条件；它本身不能证明可以独立推导。自行计算也不能仅凭数值正确证明理解全部原理。判断需结合本单元目标、实际任务及帮助条件，不统一要求口述或长篇输入。

## 4. 推荐路线与学习者决定分开

AI 负责说明前置关系、取舍和缺口，不因学习者要求而改变事实判断。学习者决定投入与顺序，了解影响后仍坚持时，执行者调整路线。

因此，暂缓前置和拒绝复习都有后续路径；它们不会被登记为掌握。后续受阻时再针对具体问题提出补足建议，不无限重复劝说。

## 5. 进度、能力与依据分开保存

总清单保存整体结构，接续页保存唯一有效的当前状态，阶段记录保留可追溯依据。材料互相引用，减少历史堆叠和重复询问。

一次阶段收束可以带有缺口。记录应回答“做过什么、用了什么帮助、能说明什么”，而非只留下“已完成”或一个总分。

## 6. 可复用的是流程，具体内容仍需核实

不同目标对应不同资料：职业任务、教材、课程要求或技能文档不能互相替代。通用流程负责资料选择、证据与调整的关系，不内置某领域的全部知识。

外部变化只在影响目标时提出调整。无法核实时说明局限，避免把模型记忆、平台热度或单个案例当成当前标准。

## 7. 执行者职责

| 执行者 | 主要责任 |
| --- | --- |
| 学习者 | 说明目标和条件，参与尝试与反馈，决定学习安排，纠正不准确记录 |
| AI 导师 | 组织资料和路线、解释与示范、分析错误、调整帮助、如实维护证据 |
| 系统实现者 | 提供资料与存储能力，保证实际可读取和更新的记录，区分教学内容与工具动作 |

个人对话工具可以人工携带记录；具备文件或状态存储的系统可以自动保存。两者都需要明确有效版本与来源。流程不要求特定模型、框架、数据库或部署平台。

## 8. 设计依据的性质

本规范采用需求与反馈驱动的流程设计：每条规则说明解决的问题、执行动作及检查方式；后续修改依据实际表现和使用反馈，而非仅增加任务数量。

这些是设计约定与合理性说明，不是教育效果实验结论。文档场景走查可以发现规则冲突和缺口；跨学习者的实际效果、长期保持和迁移仍需实际试用验证。

公开示例均为虚构，只用于说明执行逻辑。检查范围见 [验证报告](VALIDATION.md)。
